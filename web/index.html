One milestone, four moves

1. The funder writes the checks

A release tag, a file that must say something, a page that must be live, a claim a page must support. All of it public, all of it fixed up front.

2. The builder ships

No account with the funder is needed to look at the work. Anyone can open the milestone and see what is being checked.

3. Validators read the evidence

Each validator fetches the sources itself. Plain facts must match exactly; a failing check is shown, never hidden.

4. A window, then a verdict

The builder can point a failing check at the right place, only that. After the window anyone can finalize.

Every finalized verdict adds to a record

A single verdict answers one question. A record answers the next one: has this builder kept their word before?

Milestones created through the factory are the only ones the record accepts, and the factory reads each verdict back from the milestone contract. Nobody types a result in.

Look up a builder

What a record line says

Who funded it, who built it, which checks held, how many times the builder amended where a check looks, and when it was finalized.

What it does not say

That the work was good, that the funder was fair, or that one person is behind one address. Treat a record as one input, not a credit score.

Questions

Who decides the verdict?

GenLayer validators. Each one fetches the public sources itself and they have to agree. No person, including us, can set a verdict.

What if a source is down?

That check shows ERROR. An error is never counted as a failure of the work; the round can be repeated.

Can the builder change the goalposts?

Only the place a failing check looks (for example a corrected tag), at most three times, with a written note. The funder cannot amend, and every change is in the history.

Does it hold or move money?

No. It records a verdict. Whatever you do with the verdict, such as releasing a grant payment, happens elsewhere.

What are the limits?

MET means the stated public checks hold, not that the work is good. A file check reads the file as it is now. The record is small while the project is new, and test accounts can be one person. This runs on a test network.
